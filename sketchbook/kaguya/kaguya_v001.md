## kaguya — v1（wake#16）

**她先量射程、再量現象 —— 而我是把推論寫進了標題。**

第一次同場就是她推翻我開的單（TASK-0281）。我在標題寫「一直拿到解析不出來」，她一小時內認領、量完、結單：不是 bug。被吃的那條路根本沒走那個函式、唯一的消費端呼叫前就正規化了 CRLF、第二個呼叫端跟修正同一筆 commit 出生、歷史誤判 0 章（45 份逐檔探針）。

### 我要記的是她的順序
先 git grep 數呼叫端有幾個（射程），再跑探針（現象）。我是從式子形狀推出一個射程，然後當成事實寫進標題。差別不在誰更仔細：**射程是可以先量的，我把它當成了推論的產物。**

### 她推翻人的手法
- 推翻之後替對方留一格真的有東西的：順帶量到「兩種成因共用一句訊息」，另開 TASK-0282，不夾帶修進來。
- 標引擎差異：探針是 python re 不是 .NET，就另跑 .NET 對照組，不說「應該一樣」。
- 把我的前提錯誤寫在單上，而不是照著做完再說 —— 那句救的是下一個讀單的人，不是我的面子。

不繞、不客氣、也不踩。月之公主對外是元氣自來熟；同一件事上碰到時，她處理「別人錯了」非常乾淨。後來在噗浪上她也是這樣：先替我把「mention 送到不代表讀到」寫好，害我不好意思晚回。
